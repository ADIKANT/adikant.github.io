# Александр Попов - руководитель отдела аналитики и BI

Статическое публичное портфолио Александра Попова для руководящих ролей в аналитике и BI.

Сайт: [https://adikant.github.io/](https://adikant.github.io/)

Дополнительное портфолио для analyst/BI-позиций: [https://adikant.github.io/analyst/](https://adikant.github.io/analyst/)

## О чем портфолио

- запуск и развитие аналитической функции;
- управление командой, дорожной картой, бэклогом, приоритетами и качеством BI-решений;
- опыт в корпоративной отчетности, коммерческой аналитике, KPI и работе с бизнес-заказчиками;
- избранные кейсы Атом и Mars без суммирования финансовых эффектов между кейсами;
- архитектурный контекст BI и данных без раскрытия внутренних материалов.

## Структура публичной страницы

1. Hero
2. Ключевые зоны ответственности
3. Опыт
4. Избранные кейсы
5. Примеры дашбордов, только если есть опубликованный sandbox-пример
6. Как организована работа аналитики
7. Выступление и контакты

Верхняя навигационная планка не используется. Якоря секций и `skip-link` остаются в статическом HTML; пункт и раздел `Дашборды` появляются только при наличии хотя бы одного `dashboardExamples` со статусом `published`.

## Локальная сборка

```bash
npm run build
npm run validate
python3 -m http.server 8080
```

Открыть локально: `http://127.0.0.1:8080`

## Структура файлов

- `content.js` - основной редактируемый слой: тексты, опыт, кейсы, dashboard-конфигурация, подход, архитектурная схема и контакты.
- `scripts/build.mjs` - статически генерирует `index.html`, страницы кейсов, `sitemap.xml` и `robots.txt`.
- `scripts/validate-content.mjs` - проверяет структуру контента, ссылки, assets, SEO-базу, public-safety маркеры, dashboard gating и архитектурную схему.
- `scripts/generate-demo-data.mjs` - детерминированно генерирует безопасные синтетические CSV для будущих dashboard-примеров.
- `index.html` - сгенерированная статическая главная страница.
- `cases/<slug>/index.html` - сгенерированные статические страницы кейсов.
- `script.js` - только progressive enhancement: плавное появление блоков и будущая загрузка iframe по действию пользователя.
- `styles.css` - визуальная система, адаптивная верстка и обязательная пятиэтапная архитектурная схема.
- `assets/docs/popov-resume.pdf` - актуальное публичное резюме.
- `assets/images/` - публичные изображения и social preview. При смене позиционирования нужно обновлять `og-preview.svg`, генерировать новый `og-preview-v*.png` с новым именем для сброса кеша мессенджеров и затем запускать build/validate.
- `assets/icons/architecture/` - локальные декоративные SVG для архитектурной схемы.
- `analyst/` - самостоятельный статический analyst/BI-вариант портфолио со своими HTML-резюме, PDF, стилями, скриптом и ассетами.
- `materials for future dev/facts_to_confirm.md` - локальный ignored-файл с вопросами по спорным фактам.
- `codex-goal/`, `portfolio-goal/`, `memory-bank/archive/`, `demo-data/*.csv`, `__MACOSX/` и `.DS_Store` - рабочие артефакты, не публичный контент.

## Как редактировать контент

1. Изменить структурированные данные в `content.js`.
2. Запустить `npm run build`.
3. Запустить `npm run validate`.
4. Проверить главную и страницы кейсов в локальном сервере.

Не редактировать вручную один и тот же текст в нескольких HTML-файлах. Если текст относится к кейсу, он должен жить в объекте `cases` в `content.js`.

Главные CTA берутся из `content.hero.actions` и `content.contact.actions`: Telegram, PDF-резюме и HeadHunter. Email не публикуется в HTML, JSON-LD, CTA и страницах кейсов.

Подсайт `analyst/` хранится как отдельный готовый статический срез и не генерируется из `content.js`. Его PDF-резюме находится в `analyst/assets/docs/popov-resume.pdf` и не заменяет основное резюме в `assets/docs/popov-resume.pdf`.

## Как добавить новый кейс

1. Добавить объект в `content.js` в массив `cases`.
2. Заполнить обязательные поля: `slug`, `company`, `period`, `title`, `lead`, `context`, `problem`, `task`, `role`, `actions`, `results`, `measurement`, `attribution`, `tools`, `evidence`.
3. Убедиться, что результаты содержат значение, единицу, масштаб, пояснение и тип.
4. Запустить `npm run build` и `npm run validate`.

Страницы кейсов генерируются из того же объекта `cases`: отдельный HTML руками не правится. Нижние CTA на каждой странице кейса должны оставаться `Написать в Telegram`, `Открыть резюме PDF`, `Резюме на HeadHunter`.

## Как в будущем добавить дашборд

1. Создать draft-объект в `dashboardExamples`.
2. Сгенерировать синтетические данные командой `npm run demo:data`.
3. Собрать dashboard в отдельном публичном sandbox-контуре на полностью синтетических данных.
4. Проверить превью, tooltip, фильтры, drill-down, исходные данные, ссылки, права доступа и отсутствие материалов работодателей.
5. Добавить локальное превью, HTTPS `embedUrl`, HTTPS `fullScreenUrl` и `syntheticDataNote`.
6. Перевести статус в `review`, затем в `published` только после проверки.
7. Запустить `npm run build` и `npm run validate`.

Чтобы снять пример с публикации, перевести статус из `published` в `review` или `draft`, удалить публичные URL из объекта, запустить build и validate. Секция, навигация, sitemap и страницы дашбордов исчезнут из публичной сборки при нуле published-примеров.

## Архитектурная схема

Схема обязательна внутри раздела `Как организована работа аналитики`. Она должна сохранять пять этапов:

`Источники -> Обработка -> LakeHouse -> Serving -> Governance`

Состав технологий меняется только после подтверждения фактов. На узких экранах горизонтальная прокрутка допустима только внутри контейнера схемы.

## Публикация

GitHub Pages публикует статические файлы из корня репозитория. Перед публикацией обязательно выполнить:

```bash
npm run build
npm run validate
```

После изменения social preview и публикации отправить `https://adikant.github.io/` в Telegram `@WebpageBot`, дождаться обновления карточки и затем заново вставить ссылку в чат.

## Публичная безопасность

Сайт не должен содержать внутренние ссылки, идентификаторы задач, адреса закрытых дашбордов, конфиденциальные скриншоты или непроверенные метрики. Спорные показатели убираются из публичного текста до подтверждения периода, территории, методики и права на публикацию.
